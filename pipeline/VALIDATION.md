# Validation and Release Gate

This file defines what "ready to hand off" means for the complete workflow.
Generated data and heavy analysis outputs remain outside the repository.

## Release gate

A release must pass all of the following:

1. Python tests, Ruff and Mypy.
2. Bash syntax checks for every workflow shell script, on a strict LF shell
   (Linux/WSL), not only Git Bash.
3. Every shell script and `bin/wgdi` in the release archive uses LF line
   endings. The builder normalizes CRLF at packaging time; `.gitattributes`
   (`*.sh text eol=lf`, `bin/wgdi text eol=lf`) keeps checkouts LF on Windows.
4. Release ZIP construction plus CRC and checksum verification.
5. Installation from the extracted release in a clean virtual environment.
6. Core preprocessing end-to-end test from synthetic input.
7. A WGDI smoke run on derived data, with a committed or attached
   `smoke_report.json`.
8. The public receipt is generated by the collector **in the run environment**
   (`--public`, or the runner's `smoke_report.public.json`). Never re-probe tool
   versions from a different shell afterwards: the collector reads `PATH`, so a
   later collection can record a different environment than the one that ran.
9. The receipt records OS, Python, WGDI and external-tool versions.
10. Both downstream modes are exercised: the default core mode (dotplot +
    collinearity, 2 products) and the opt-in Ks mode (`WGDI_KS=true`, 8
    products), each with a PASS receipt.

The synthetic preprocessing test is included in the Python test suite. A WGDI
smoke receipt depends on DIAMOND, MUSCLE, yn00, Perl and WGDI being installed on
the validation host. PAL2NAL is installed separately from its official source
with `python code/tools/install_pal2nal.py`; the release archive does not
redistribute the historical v14 archive.

## Local checks

From `code/`:

```powershell
python -m pytest -q
python -m ruff check src tests scripts tools
python -m mypy src --ignore-missing-imports
```

From the workflow root with Git Bash available:

```bash
for script in *.sh code/tools/*.sh; do bash -n "$script"; done
```

Build and inspect a source release:

```powershell
python code/tools/build_release_package.py `
  --output dist/plant-genome-preprocess-v3.8.0.zip
```

The ZIP includes its own `PACKAGE_SHA256.tsv`; the build command prints the
archive SHA-256 and performs a CRC check.

## WGDI smoke run

The release gate includes a self-contained synthetic fixture:

```powershell
python code/tools/build_synthetic_wgdi_smoke.py `
  --workflow-root <workflow-root> `
  --output-root <workflow-root/smoke_synthetic> `
  --genes-per-species 120 --chromosomes 8 --protein-length 80

bash code/tools/run_wgdi_smoke.sh <workflow-root/smoke_synthetic>
```

The resulting `smoke_report.json` must be PASS for every comparison. A released
package is not considered end-to-end validated without a passing report. A
derived real-data smoke can additionally be built with
`build_wgdi_smoke_fixture.py`.
